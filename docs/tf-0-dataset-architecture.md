# TF-0 — Tau Dataset Architecture

**Status:** Architecture design (TF-0)  
**Not implemented:** No data collected, no downloads, no storage provisioned

---

## Principle

Tau must **not** download someone else's dataset and rename it "Tau Dataset."

Every record requires **provenance, license, and ownership classification**.

---

## Provenance taxonomy

| Class | Definition | Ownership clarity | Example |
|-------|------------|-------------------|---------|
| **THIRD-PARTY DATA** | Externally sourced, used under license | Licensed, not owned | OpenOrca (verify license), SlimOrca |
| **TAU-CREATED DATA** | Authored by Tau team or contractors under Tau agreement | Highest | Constitution exemplars, ecosystem task prompts |
| **TAU-TRANSFORMED DATA** | Derived from permitted third-party via documented transforms | Tau owns transform + selection | Filtered/deduplicated instruction mix |
| **TAU-SYNTHETIC DATA** | Generated using LLM/API | **REQUIRES LEGAL REVIEW** | GPT-generated examples reviewed by humans |
| **TAU-LICENSED DATA** | Acquired under explicit data license | Contract-dependent | Future vendor datasets |

**Critical:** Data generated by a third-party model (Qwen, GPT, Claude, etc.) is **not automatically Tau-owned**. Terms of the generator API/license govern use for training.

## Tau-synthetic data policy

Synthetic generation may accelerate coverage but carries legal and quality risk.

| Rule | Policy |
|------|--------|
| Generator | Document model + API terms at time of generation |
| Review | Human review required before `approved` status |
| Ownership | Mark `REQUIRES_LEGAL REVIEW` until counsel confirms |
| Contamination | Do not eval on synthetic-near duplicates |
| Labeling | Never present synthetic data as human-authored |

---

## Contamination controls

1. **Benchmark holdout:** Reserve MMLU/HumanEval/etc. slices — do not train on benchmark text
2. **Dedup:** MinHash/simhash across all sources + against eval sets
3. **N-gram overlap scan:** Flag >80% overlap with eval prompts
4. **Version pinning:** Dataset version hash in every training run manifest

---

## Memory boundary (dataset ↔ product)

Training data may include **product-scoped examples** (TauMail drafts) but must not embed **real user PII** or private mailbox content without consent and governance.

Product memory (AI-5) and training corpus are **separate systems**. Promotion from product memory to training data requires explicit policy — not automatic.

## Split policy

| Split | Ratio | Purpose |
|-------|-------|---------|
| Train | 90% | SFT/DPO |
| Validation | 5% | Hyperparameter tuning |
| Test | 5% | Held-out — **never** used during training decisions |

Stratify by category and product_context.
